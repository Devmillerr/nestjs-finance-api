# Security checklist — OWASP API Security Top 10 (2023)

Honest self-review against the [OWASP API Security Top 10](https://owasp.org/API-Security/editions/2023/en/0x11-t10/). Not a compliance certification — a working checklist, including what's genuinely not addressed yet.

| # | Risk | Status | Notes |
|---|---|---|---|
| API1 | Broken Object Level Authorization | ✅ Addressed | `OwnershipGuard` on every single-resource endpoint (`purchases`, `budgets`, `invoices`, `service-contracts`, `users`). A `USER` can never read or act on another user's resource by guessing an ID — verified with real ownership tests conceptually covered by the guard's logic; ADMIN/OWNER bypass is explicit, not accidental. |
| API2 | Broken Authentication | ✅ Addressed | JWT access + refresh, refresh rotation with reuse detection (a reused, already-rotated token revokes every active session for that user), bcrypt (12 rounds) for passwords, rate-limited login (`@Throttle`), generic error message on failed login (no user enumeration). |
| API3 | Broken Object Property Level Authorization | ✅ Addressed | Global `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true })` — any field not declared in a DTO is stripped or rejected. Mass assignment (e.g. a client sending `role: "ADMIN"` in a profile update) is structurally impossible, not just filtered by convention. |
| API4 | Unrestricted Resource Consumption | ✅ Addressed | Global rate limiting (`@nestjs/throttler`, 100 req/min default, 5 req/min on login), pagination (`page`/`limit`, max 100) on every list endpoint — no unbounded `findMany()` anywhere. |
| API5 | Broken Function Level Authorization | ✅ Addressed | Default-deny: `JwtAuthGuard` is global, `@Public()` is the explicit opt-out. `@Roles()` and `@RequirePermissions()` stack on top for admin-only mutations (issuing invoices, changing contract status, deleting resources). |
| API6 | Unrestricted Access to Sensitive Business Flows | 🟡 Partially addressed | `Idempotency-Key` on the two payment-critical creates (`purchases`, `invoices`) prevents duplicate financial records from retries. Not addressed: no anti-automation control (CAPTCHA, device fingerprinting) on `register` — acceptable for the current scope, would need revisiting before handling real signups at scale. |
| API7 | Server Side Request Forgery | ⚪ Not applicable yet | No endpoint currently fetches a user-supplied URL server-side. Flagged for re-review if/when webhooks, PDF generation from a URL, or image-fetch-by-URL features are added — that's exactly where this risk would appear. |
| API8 | Security Misconfiguration | ✅ Addressed | `helmet`, explicit CORS origin from env (no wildcard reflection — V2's original bug), secrets in `.env` never in source control, structured logs with automatic redaction of `authorization`/`cookie`/`password`/`refreshToken`, Row Level Security enabled with deny-by-default on every Supabase table. |
| API9 | Improper Inventory Management | ✅ Addressed | Versioned API (`/api/v1`), live OpenAPI docs at `/docs` generated from the actual DTOs (can't drift from reality the way hand-written docs do). One environment (Supabase project `Financeapi`) — no shadow/forgotten staging APIs to lose track of yet. |
| API10 | Unsafe Consumption of APIs | ⚪ Not applicable yet | This API doesn't currently call any third-party API itself (no payment gateway integration, no external webhook consumption). Flagged for review whenever Stripe/PayPal integration is actually wired up — trusting their payloads blindly would be exactly this risk. |

## Known gaps, not yet closed

- **Dependency vulnerabilities: down from 26 to 17 via targeted `overrides`** in `package.json` (`qs`, `multer`, `body-parser`, `lodash`, `file-type`, `js-yaml` bumped to patched versions without touching `@nestjs/platform-express`'s major version). Verified with `npm audit --omit=dev`, not assumed.
  - **13 remaining are dev-only tooling** (`@nestjs/cli`'s own webpack/inquirer/tmp chain) — not shipped to production.
  - **4 remaining are moderate-severity, in production, and currently unpatchable without a breaking change**: [`GHSA-36xv-jgw5-4q75`](https://github.com/advisories/GHSA-36xv-jgw5-4q75), an injection issue (CWE-74, CVSS 6.1) in `@nestjs/core` itself, affecting **every version up to and including 11.1.17** — Nest 11 doesn't fix it either, only Nest 12 does. Deferred on purpose: the fix requires the same major-version jump that was already ruled out in Phase 0 for ecosystem-compatibility reasons (see `ARCHITECTURE.md`). This is a real trade-off, not an oversight — worth revisiting if/when the Nest 12 ecosystem (Prisma, Passport, `@nestjs/config` etc.) stabilizes enough to migrate.
- No secrets scanning pre-commit hook (risk: a `.env` accidentally committed). `.gitignore` already excludes `.env`, but that's a single point of failure, not a control.
- No automated RLS policy tests against Supabase (the current policy is "deny everything," which is easy to reason about now, but if per-row policies are ever added instead of relying on the app layer, they need their own test coverage).
